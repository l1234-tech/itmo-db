# Теория к лабораторной работе № 1

Конспект по вопросам к защите лабораторной работы о моделировании БД и PostgreSQL. Примеры ориентированы на PostgreSQL.

## 1. БД, СУБД и РСУБД

**База данных (БД)** — организованный набор связанных данных. **СУБД** — программная система для описания структуры данных, выполнения запросов, контроля доступа, транзакций и восстановления. **Реляционная СУБД (РСУБД)** хранит данные в таблицах-отношениях, а связи выражает ключами.

Файлы подходят для простого хранения, но СУБД обеспечивает ограничения целостности, конкурентный доступ, транзакции, индексы, язык запросов, разграничение прав и резервное восстановление.

## 2. Концептуальная, логическая и физическая модели; нотация Чена

- **Концептуальная модель** описывает предметную область независимо от конкретной СУБД: сущности, атрибуты, связи и кратности.
- **Логическая модель** превращает концептуальное описание в структуру выбранной модели данных, например реляционные таблицы, ключи и связи.
- **Физическая модель** уточняет типы столбцов, индексы, ограничения, последовательности и детали реализации.
- В **нотации Чена** сущности обычно изображают прямоугольниками, атрибуты — овалами, связи — ромбами. Кратности сообщают, сколько экземпляров могут участвовать в отношении.

Связь M:N обычно реализуют отдельной таблицей-связкой с внешними ключами на обе сущности. Атрибуты самой связи хранят в этой таблице. Тернарная связь описывает одно отношение сразу между тремя сущностями. В реляционной реализации она часто превращается в таблицу со ссылками на все три сущности. Разбивать её на бинарные связи можно только после анализа смысла: бездумное разбиение способно потерять семантику или породить лишние комбинации.

## 3. Рекурсивная связь

Рекурсивная связь — связь экземпляров сущности с экземплярами той же сущности. Например, сотрудник руководит другим сотрудником. В таблице это внешний ключ на саму таблицу:

    CREATE TABLE сотрудник (
        id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
        имя text NOT NULL,
        руководитель_id bigint REFERENCES сотрудник(id)
    );

Поле руководитель_id ссылается на сотрудник.id; NULL может обозначать отсутствие руководителя.

## 4. Архитектура ANSI-SPARC

Архитектура ANSI-SPARC выделяет три уровня:

1. **Внешний** — пользовательские представления и подмножества данных.
2. **Концептуальный** — общая логическая структура всей базы данных.
3. **Внутренний** — физическое размещение, индексы, страницы и способы доступа.

Разделение повышает независимость данных: изменение физического хранения не должно требовать обязательного изменения пользовательских представлений.

## 5. Первичный и внешний ключи; ссылочная целостность

**PRIMARY KEY** однозначно идентифицирует строку, уникален и не допускает NULL. **FOREIGN KEY** требует, чтобы каждое ненулевое ссылочное значение указывало на существующую строку в целевой таблице. Это и есть один из главных механизмов ссылочной целостности.

    CREATE TABLE книга (
        id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
        название text NOT NULL
    );

    CREATE TABLE чтение (
        герой_id integer NOT NULL,
        книга_id bigint NOT NULL REFERENCES книга(id),
        PRIMARY KEY (герой_id, книга_id)
    );

Внешний ключ можно добавить после создания таблицы:

    ALTER TABLE чтение
    ADD CONSTRAINT чтение_книга_fk
    FOREIGN KEY (книга_id) REFERENCES книга(id);

Существующие строки должны удовлетворять ограничению. Имена ограничений помогают обращаться к ним при миграциях.

### Удаление или изменение родительской строки

- **ON DELETE NO ACTION** — операция не проходит, если после неё нарушается ограничение; проверка может быть отложенной, если constraint объявлен DEFERRABLE.
- **ON DELETE RESTRICT** — немедленно запрещает удаление родительской строки при наличии ссылок.
- **ON DELETE CASCADE** — удаляет связанные дочерние строки.
- **ON DELETE SET NULL** — ставит внешний ключ в NULL, поэтому столбец должен это допускать.
- **ON DELETE SET DEFAULT** — устанавливает значение по умолчанию, которое всё равно должно удовлетворять внешнему ключу.

Аналогичные действия ON UPDATE применяются при изменении ключа. Каскадное удаление полезно, когда дочерняя запись не имеет самостоятельного смысла, но применять его следует аккуратно.

### Две таблицы, ссылающиеся друг на друга

Циклические внешние ключи возможны. Часто сначала создают обе таблицы, а недостающее ограничение добавляют через ALTER TABLE. При вставке взаимозависимых строк иногда требуется DEFERRABLE-ограничение, чтобы проверка происходила к концу транзакции.

## 6. NULL и логика SQL

NULL означает неизвестное или отсутствующее значение, а не обычное значение. Поэтому NULL = NULL не даёт TRUE: сравнение возвращает UNKNOWN. WHERE оставляет только строки, условие которых истинно.

    SELECT * FROM герой WHERE прозвище IS NULL;
    SELECT * FROM герой WHERE прозвище IS NOT NULL;

COALESCE(x, 0) возвращает 0, если x равен NULL. IS DISTINCT FROM сравнивает значения, обрабатывая NULL как отдельное сравнимое состояние.

В PostgreSQL обычный UNIQUE допускает несколько NULL, потому что NULL-значения не считаются равными в обычном сравнении уникальности. В современных версиях PostgreSQL существует UNIQUE NULLS NOT DISTINCT. Если значение должно быть обязательным и уникальным, используют UNIQUE и NOT NULL вместе.

## 7. CHECK, CONSTRAINT, DOMAIN и TYPE

CONSTRAINT — ограничение целостности: NOT NULL, CHECK, UNIQUE, PRIMARY KEY, FOREIGN KEY. Пример ограничения значения в диапазоне:

    CREATE TABLE персонаж (
        id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
        имя text NOT NULL,
        веселость integer NOT NULL DEFAULT 5,
        CONSTRAINT веселость_диапазон CHECK (веселость BETWEEN 1 AND 10)
    );

CHECK предназначен для проверки выражения по значениям текущей строки. В PostgreSQL нельзя надёжно определять CHECK, который обращается к другой таблице: он не гарантирует межтабличную целостность при последующих изменениях. Для межтабличных правил применяют FOREIGN KEY, уникальные ограничения, триггеры или изменения модели.

**DOMAIN** — тип на основе существующего типа с дополнительными правилами:

    CREATE DOMAIN положительный_балл AS integer CHECK (VALUE > 0);

**CREATE TYPE** создаёт пользовательский тип PostgreSQL, например ENUM, составной тип или другой вид пользовательского типа. DOMAIN уточняет правила допустимых значений базового типа; TYPE может определять отдельный набор значений или структуру.

У домена можно задать NOT NULL, CHECK и значение по умолчанию. Его применяют, когда одно правило должно использоваться в нескольких столбцах.

## 8. ENUM

ENUM — пользовательский перечислимый тип с фиксированными строковыми метками:

    CREATE TYPE вид_добычи AS ENUM ('моллюски', 'устрицы');
    CREATE TABLE сбор (
        id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
        добыча вид_добычи NOT NULL
    );

Метками ENUM являются строки, а не числа. Порядок меток соответствует порядку объявления. Значение можно добавить через ALTER TYPE ... ADD VALUE. Удаление и переупорядочивание существующих значений обычно требует миграции или пересоздания типа.

## 9. DDL, DML, DQL и DCL

- **DDL** (Data Definition Language) — определение структуры: CREATE, ALTER, DROP.
- **DML** (Data Manipulation Language) — изменение данных: INSERT, UPDATE, DELETE, MERGE.
- **DQL** (Data Query Language) — получение данных, обычно SELECT. В некоторых классификациях SELECT включают в DML.
- **DCL** (Data Control Language) — управление правами: GRANT, REVOKE.

ALTER изменяет структуру объекта, например добавляет столбец; UPDATE изменяет значения уже существующих строк.

    ALTER TABLE герой ADD COLUMN возраст integer;
    UPDATE герой SET возраст = 25 WHERE имя = 'Гарин';

## 10. Системный каталог и структура таблиц

Системный каталог содержит метаданные о схемах, таблицах, типах, столбцах и ограничениях. В PostgreSQL примеры — pg_class, pg_attribute, pg_constraint и стандартные представления information_schema.

    SELECT version();
    SELECT current_user, current_schema();
    SELECT schema_name FROM information_schema.schemata ORDER BY schema_name;
    SELECT table_schema, table_name
    FROM information_schema.tables
    WHERE table_type = 'BASE TABLE'
    ORDER BY table_schema, table_name;

Если таблица «не существует», возможные причины: опечатка или неверный регистр/кавычки; таблица находится в другой схеме; нужная схема не включена в search_path; подключение выполнено не к той базе.

    SHOW search_path;
    SELECT to_regclass('схема.таблица');
    SELECT * FROM схема.таблица;

Схема — пространство имён внутри базы. Раздельные схемы помогают организовывать объекты, назначать права и избегать совпадений имён. В учебной среде студенты могут иметь собственные схемы.

**Роль** — объект авторизации, которому выдаются права. В PostgreSQL пользователь — роль с атрибутом LOGIN; роли также могут представлять группу общих прав.

## 11. INTEGER, SERIAL, IDENTITY и SEQUENCE

INTEGER — тип данных, не генерирующий значения автоматически. SERIAL — сокращение PostgreSQL, которое создаёт целочисленный столбец, последовательность и DEFAULT nextval(...). GENERATED ... AS IDENTITY — стандартный механизм автоидентификатора, связанный с последовательностью.

    CREATE TABLE пример (
        id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
        значение text NOT NULL
    );

- **GENERATED ALWAYS AS IDENTITY** обычно запрещает ручную подстановку идентификатора без OVERRIDING SYSTEM VALUE.
- **GENERATED BY DEFAULT AS IDENTITY** допускает явно указанное значение ID.
- **SERIAL** — удобное расширение PostgreSQL; в новом коде обычно предпочитают IDENTITY.

Работа с последовательностью:

    CREATE SEQUENCE пример_seq START WITH 1 INCREMENT BY 1 CACHE 20;
    SELECT nextval('пример_seq');
    SELECT currval('пример_seq'); -- после nextval в этой сессии
    ALTER SEQUENCE пример_seq RESTART WITH 1;

Последовательности не гарантируют нумерацию без пропусков: значение, полученное в транзакции, не возвращается при ROLLBACK. Удаление строки обычно не переиспользует её ID. Удаление таблицы или identity-столбца может удалить принадлежащую ему последовательность.

После INSERT идентификатор обычно удобнее получить через RETURNING:

    INSERT INTO герой (имя, бодрствует)
    VALUES ('Зоя', TRUE)
    RETURNING id_героя;

## 12. VARCHAR, CHAR, TEXT и NUMERIC

- **CHAR(n)** — фиксированная длина, короткие значения дополняются пробелами.
- **VARCHAR(n)** — переменная длина с ограничением.
- **TEXT** — переменная длина без указанного ограничения.

В PostgreSQL нет общего выигрыша в производительности у VARCHAR(n) перед TEXT. Ограничение длины стоит задавать, если оно является требованием предметной области.

NUMERIC хранит точные десятичные числа; NUMERIC(p, s) задаёт общее число значащих цифр p и цифр после десятичной точки s. NUMERIC(7,2), например, допускает до пяти цифр до точки и две после неё.

## 13. TIMESTAMP и TIMESTAMPTZ

TIMESTAMP WITHOUT TIME ZONE хранит дату и время без информации о часовом поясе. TIMESTAMPTZ представляет момент времени: PostgreSQL нормализует его внутреннее значение и отображает в часовом поясе сессии. Имя исходного часового пояса в значении TIMESTAMPTZ не сохраняется.

## 14. INSERT, DELETE, ORDER BY и агрегатные функции

Вставка нескольких строк:

    INSERT INTO герой (имя, бодрствует)
    VALUES ('Гарин', FALSE), ('Зоя', TRUE);

Удаление строк:

    DELETE FROM герой WHERE имя = 'Гарин';

Без WHERE DELETE удаляет все строки таблицы. Перед опасным удалением полезно выполнить SELECT с тем же условием.

Сортировка:

    SELECT * FROM герой ORDER BY имя ASC NULLS LAST;

По умолчанию сортировка — ASC. В PostgreSQL NULL по умолчанию находится в конце для ASC и в начале для DESC; NULLS FIRST и NULLS LAST задают порядок явно.

Агрегатные функции: COUNT, SUM, AVG, MIN, MAX. Большинство агрегатов игнорирует NULL. COUNT(*) считает строки, COUNT(столбец) — только строки, где столбец не NULL. AVG возвращает NULL, если в группе нет ненулевых значений.

WHERE фильтрует строки до группировки; GROUP BY формирует группы; HAVING фильтрует группы после вычисления агрегатов.

    SELECT группа, AVG(балл)
    FROM результаты
    WHERE дата >= DATE '2026-01-01'
    GROUP BY группа
    HAVING AVG(балл) >= 4;

SELECT * означает все столбцы результирующего набора источников запроса. При соединении это обычно столбцы обеих таблиц. Явный список столбцов делает запрос более понятным и менее хрупким к изменениям схемы.

## 15. Логический порядок SELECT

Для понимания запроса удобно помнить приближённый логический порядок:

1. FROM и JOIN — источники данных и соединение строк.
2. WHERE — фильтрация строк.
3. GROUP BY — формирование групп.
4. HAVING — фильтрация групп.
5. SELECT — вычисление столбцов.
6. DISTINCT — удаление дубликатов, если указано.
7. ORDER BY — сортировка.
8. LIMIT и OFFSET — ограничение и смещение результата.

Это логическая модель, а не обязательный физический план: оптимизатор может менять план, сохраняя семантику.

## 16. Транзакции, ACID, BASE и CAP

**Транзакция** — группа операций, рассматриваемая как единое целое. BEGIN начинает транзакцию, COMMIT фиксирует изменения, ROLLBACK отменяет ещё не зафиксированные изменения. В режиме autocommit каждая успешная команда обычно фиксируется как отдельная транзакция.

**ACID:** Atomicity — всё или ничего; Consistency — сохранение ограничений; Isolation — изоляция параллельных транзакций; Durability — сохранение зафиксированных изменений при сбое согласно гарантиям системы.

**BASE** — подход, ассоциируемый с доступностью и eventual consistency: Basically Available, Soft state, Eventual consistency. Это не единый стандарт транзакций.

**CAP** описывает компромисс в распределённой системе при сетевом разделении: нельзя одновременно гарантировать полную Consistency и Availability во всех случаях Partition. При разделении сетью система выбирает, каким свойством пожертвовать для затронутых запросов.

## 17. STI, MTI и CTI

Термины обычно относятся к стратегиям отображения наследования в реляционной БД:

- **STI (Single Table Inheritance)** — одна таблица для базового типа и всех подтипов; discriminator хранит тип строки. Запросы проще, но возможно много NULL и сложные ограничения.
- **CTI (Class Table Inheritance)** — отдельная таблица для базового класса и каждого подтипа; идентификаторы связываются внешними ключами. Структура нормализованнее, но чаще нужны JOIN.
- **MTI (Multiple Table Inheritance)** трактуется неодинаково в разных ORM и курсах, часто как наследование через несколько таблиц. Точную расшифровку для курса следует сверить с лекциями преподавателя.

## 18. RAISE NOTICE

RAISE NOTICE выводит информационное сообщение клиенту и помогает отлаживать блоки PL/pgSQL.

    DO $$
    DECLARE
        число integer := 3;
    BEGIN
        RAISE NOTICE 'Значение: %', число;
    END $$;

Символ % заменяется переданным аргументом. Другие уровни сообщений включают DEBUG, INFO, WARNING и EXCEPTION; EXCEPTION приводит к ошибке.

## 19. Краткие ответы на типовые вопросы

- **Что будет при удалении связанной сущности?** Действует правило внешнего ключа: RESTRICT, NO ACTION, CASCADE, SET NULL или SET DEFAULT.
- **Как расширить модель?** Определить новую сущность/атрибут и ограничения, обновить концептуальную и логическую модели, затем выполнить миграцию таблиц и ключей.
- **Как сменить тип столбца без потери данных?** Проверить возможность преобразования, сделать резервную копию и использовать ALTER TABLE ... ALTER COLUMN ... TYPE ... USING выражение. Проверить индексы и ограничения.
- **Как добавить FK после создания таблицы?** ALTER TABLE ... ADD CONSTRAINT ... FOREIGN KEY (...) REFERENCES ...
- **Как узнать версию PostgreSQL?** SELECT version() или SHOW server_version.
- **Как ограничить количество строк и сместить результат?** LIMIT n OFFSET k; для стабильной пагинации задать ORDER BY.
- **Что означает ON DELETE RESTRICT?** Не разрешает удалить родительскую строку при существующих ссылках.
- **Можно ли в CHECK обратиться к другой таблице?** Обычный CHECK рассчитан на строку текущей таблицы и не гарантирует корректность межтабличных условий.
